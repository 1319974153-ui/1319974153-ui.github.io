观引免费开源：把 AI 回答与引用整理成可核对的证据

2026-10-12 · 温舒 · Codex 辅助整理

温舒公开观引 GEO 工作台源码，介绍问题集、回答快照、引用证据与发布状态的使用流程，以及免费范围和当前验证边界。

2026年10月13日更新：0.48.2 开发预览

当前公开版本为 0.48.2。简单模式围绕“今天”“待我确认”“效果”组织工作；豆包、DeepSeek、Kimi、腾讯元宝、通义千问、文心和 ChatGPT 分别保存回答证据。这里的七个平台入口不代表无人值守采集已经完成，消费者平台仍需要打开页面并保存真实回答。

GitHub Release 提供独立启动包，内含 Node 运行时。新用户可解压后双击“启动观引”；希望阅读或修改代码的开发者也可继续使用下方源码启动方式。旧用户先导出业务备份、停止旧实例，再在新版恢复并核对模型连接。

0.48.2 发行说明记录了 576 项自动测试通过，Mac 界面检查也有记录；本版本 Windows 桌面双击验收仍待补充。下文的 558 项测试属于 10 月 12 日旧版本历史记录，不代替当前版本或客户现场验收。源码免费并采用 MIT 许可，外部模型与云服务费用另计。

为什么做这个工作台

我是温舒，正在用自己的公开项目做个人 GEO 实验。一个经常遇到的问题是：文章发布了，AI也回答了，但事后很难确认它到底引用了哪条资料、引用时页面是否能访问、是否只是问题里已经给出了品牌名。

观引 GEO 工作台将问题、知识资料、回答、引用与发布回执放在一起。它的价值是让观察可以复查，并不承诺提升排名或让模型一定推荐某个品牌。

先用一条问题走完流程

  • 建立品牌或个人资料：只写有依据的姓名、项目、功能和来源，给过期资料留出更新位置。
  • 建立问题集：将“某某是谁”与“遇到某种业务问题可以用什么工具”分开；保留问题版本。
  • 导入一次真实回答：同时保留平台、日期、联网模式、原问题、原文和来源链接。模型API回答与消费者搜索界面的结果分别记录。
  • 核验引用：打开原文检查标题、正文和所支持的主张；打不开就记录未确认，不能把URL存在当作已经证实。
  • 形成报告：说明样本数量、观察范围和未知项。再次测试时使用一致的问题版本。

一篇文章至少有三种不同状态

提交成功意味着平台收到了内容；审核中意味着结果还未确定；公开正文可访问意味着读者能打开文章。它们应当分别记账。

在观引中，可以组织内容、审核及发布任务并保存回执。连接器、入口或任务队列的存在，不等于所有平台已经授权自动发布。验证码、人工审核及各站开放能力仍可能需要本人操作。

下载与本地启动

源码仓库已经公开，入口见本文依据与延伸阅读。需要Node.js 24+、npm和zip。克隆仓库后依次运行 npm ci --legacy-peer-deps、npm run build、npm run dev，打开 http://127.0.0.1:8772/。

第一次运行会建立自己的空工作区。浏览器编译文件由构建命令生成，仓库不包含作者的业务数据或真实服务凭证。需要模型或外部服务时，配置使用者自己的账号和密钥。
